# 因子泄露检测脚手架搭建指南

本练习学习如何组织一个用于检测因子代码中未来信息泄露的 Python 项目。仓库已经提供脚手架；你可以先运行它，再沿着下面的步骤阅读各模块，最后完成检测器和测试。也可以参照这些模块，在新目录中搭建自己的版本。

**当前状态：** 模拟数据、示例因子和报告接口已经提供，`detect_leaks` 有意留空。实现之前，检测管线会报告“检测逻辑尚未实现”，这是预期行为。

## 1. 要解决什么问题？

假设要在当天根据已知数据计算因子，却在代码里使用了明天的收盘价。历史回测时，这种写法可能让结果看起来很好，但交易时无法获得明天的数据。

项目把问题拆成几个可独立理解的部分：

```text
生成模拟行情 → 注册因子函数 → 检测未来依赖 → 导出检测报告
                  ↑              ↑
            安全和泄露示例    需要学员实现
```

练习目标：理解每个模块如何协作，使用时间前推重算检查因子函数，并编写测试说明检测器能够发现什么、不能证明什么。

## 2. 准备环境并运行现有脚手架

需要 Git 和 Python 3.10–3.12。在终端中执行：

```bash
git clone https://github.com/PKUAFT/leak-detector-starter.git
cd leak-detector-starter
python -m venv .venv
```

激活虚拟环境：

```bash
# macOS / Linux / Git Bash
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

然后安装依赖、生成数据并运行已有测试：

```bash
python -m pip install -e ".[dev]"
python tests/tools/regenerate_data.py
python tests/tools/preview_data.py -n 5
python -m pytest
```

`pyproject.toml` 记录项目依赖和测试配置；`.[dev]` 还会安装 pytest。生成命令默认写入并覆盖 `outputs/sample_factors.csv`，可通过 `--output outputs/other_sample.csv` 指定其他路径。`outputs/` 被 Git 忽略。

基础测试通过只说明已有数据和入口检查通过，并不表示检测器已经实现。完成练习前直接运行 `python tests/tools/run_pipeline.py` 会提示检测逻辑尚未实现。

## 3. 搭建项目结构

一个便于扩展的脚手架可以按职责拆分。当前仓库的主要文件如下：

```text
leak-detector-starter/
├── pyproject.toml                 # 依赖、安装和 pytest 配置
├── src/
│   ├── factors/
│   │   ├── __init__.py            # 因子定义和注册表
│   │   └── sample_factors.py      # 示例因子函数
│   └── leak_detection/
│       ├── data.py                # 数据读取和描述
│       ├── simulator.py           # 生成模拟行情
│       ├── detector.py            # 检测接口和待实现逻辑
│       ├── pipeline.py            # 连接数据、检测器和报告
│       └── reporting.py           # 输出 CSV、JSON、Markdown
├── tests/
│   ├── test_dataset.py            # 数据与因子接口检查
│   ├── test_project_entrypoints.py # 命令入口检查
│   └── tools/                     # 手动执行的辅助脚本
└── outputs/                       # 本地生成，初始时可能不存在
```

自己从零搭建时，先创建目录和 Python 包，再按下面的顺序实现模块。每一步都可以对照仓库里的同名文件；无需一次性写完所有功能。

## 4. 准备模拟数据

在 `src/leak_detection/simulator.py` 中，`generate_dataset` 使用固定随机种子，默认生成 3 只模拟股票、各 60 个工作日的数据。每行包含 `date`、`symbol`、OHLCV 和 `ret_1d`。

在 `src/leak_detection/data.py` 中，`load_sample_factors` 从 CSV 读取日期，并按股票和日期排序。`describe_dataset` 汇总记录数、股票和日期范围。生成和预览分别由 `tests/tools/regenerate_data.py`、`tests/tools/preview_data.py` 调用。

自己实现时，至少检查：

- 行情有明确的股票标识和日期，每只股票按时间顺序排列。
- 固定随机种子可复现实验；测试使用临时目录，避免依赖已有输出文件。
- 数据生成器不会把模拟数据描述为真实行情或历史时点数据。

## 5. 定义和注册因子

`src/factors/sample_factors.py` 中的因子函数接收 `DataFrame`，返回与输入行索引对齐的 `Series`。例如，下面的示例故意把明天的收盘价放到今天的计算中：

```python
def factor_future_return(df):
    forward_close = df.groupby("symbol", sort=False)["close"].shift(-1)
    return (forward_close - df["close"]) / df["close"]
```

同一文件还提供滞后收益 EMA 和滞后成交量均值两个历史因子。计算前应保证每只股票的数据按日期排序；`groupby` 本身不会替你完成时间排序。

`src/factors/__init__.py` 用 `FactorDefinition` 保存名称、函数和说明，并由 `get_registered_factors()` 返回注册表。检测器遍历注册表调用因子函数，因此新增因子时无需修改管线。`is_intentional_leak` 是教学示例的标记，检测实现不应依赖它或因子名称来判断结果。

## 6. 设计检测器接口

`src/leak_detection/detector.py` 定义了检测结果：

- `LeakViolation`：一个疑似问题，包括因子名、信号类型、置信度字段和细节。
- `LeakDetectionResult`：已检查的因子名、疑似问题列表和可选说明。
- `detect_leaks`：接收行情、因子注册表、实体列名、时间列名及数值容差；目前抛出 `NotImplementedError`，由学员完成。

实现前先约定输出字段、缺失值处理和容差含义。`confidence` 只是结果结构中的字段；若没有校准方法，不要把它解释成发生泄露的概率。`details` 若包含日期等对象，导出 JSON 前要转换成可序列化的值。

## 7. 实现前推重算练习

一个可行的基本思路是：

1. 使用完整数据运行一个因子函数，保存每行结果。
2. 对每个检查日期 `as_of`，截取所有 `date <= as_of` 的数据，保留该日期的完整股票截面。
3. 用截取后的数据重新运行同一个因子函数，将 `as_of` 当天的结果与完整数据中对应的行比较。
4. 对超过容差或缺失状态不一致的结果，记录因子、日期、股票和比较结果，再分析原因。
5. 对所有注册因子重复，返回 `LeakDetectionResult`。

注意使用稳定的实体—日期键或明确的索引来对齐结果，处理因子预热期、缺失值、浮点误差、乱序和重复键。不要简单按当前 DataFrame 的前 N 行截取：数据按股票排序时，前 N 行不一定构成某个日期以前的完整市场截面。

最低练习目标是在提供的模拟数据上识别 `factor_future_return`，同时不误报另外两个示例因子。应使用另外构造的因子和数据检验实现，避免只针对示例名称或某种写法硬编码。前推结果不一致是调查线索，也可能由排序、索引或函数状态等因素造成，需要进一步分析。

## 8. 连接管线和报告

`src/leak_detection/pipeline.py` 的 `run_pipeline` 依次加载数据、取得注册因子、调用检测器，再使用 `src/leak_detection/reporting.py` 导出结果。完成检测器后，从仓库根目录运行：

```bash
python tests/tools/run_pipeline.py --output outputs/manual
```

预期输出：

- `outputs/manual/summary.csv`：疑似问题摘要。
- `outputs/manual/violations.json`：疑似问题和细节。
- `outputs/manual/report.md`：可阅读的 Markdown 报告。

打开报告，检查因子名称、日期和比较结果是否能支持自己的判断。未发现可疑信号不等于证明没有泄露。

## 9. 测试与交付

在 `tests/` 中添加测试，至少覆盖：

- 有未来依赖的因子被识别；历史因子不因正常的预热缺失值被误报。
- 多只股票同一天的数据、输入顺序、索引对齐和数值容差。
- 一个可用的检测器能通过管线产生三种报告，报告内容与检测结果一致。

当前 `tests/test_project_entrypoints.py` 中的 `test_pipeline_reports_the_intentional_exercise_placeholder` 专门验证**初始占位状态**。完成检测器后，原测试期待管线失败，会与成功运行冲突；请同步调整该测试，例如注入一个明确抛出 `NotImplementedError` 的测试检测器来检查错误提示，并另测成功管线。不要单纯删除相关验证。

提交前运行 `python -m pytest` 和上面的管线命令，并整理一份简短说明：实现思路、测试结果、已知局限和报告示例。基础测试通过不代表检测器已覆盖所有因子。

## 10. 练习边界

本项目的数据是模拟行情。前推重算只能检查特定函数、输入和运行条件下的未来依赖，无法确认财报实际发布时间、供应商修订、历史股票池或真实数据的 point-in-time 可用性，也不能证明整个研究流程没有泄露。

有关这些问题，可继续阅读[数据的前视偏差分析](../reference/数据的前视偏差分析.md)。
